# 演示视频大纲：AI 合同系统

> 时长 ≤ 10 分钟，录屏 + 口播。演示前先 `.\start_all.ps1` 一键启动全部服务（FastAPI + Odoo），避免中途报错。

## 总时长分配（约 9 分钟，留 1 分钟余量）

| 段落 | 时长 | 内容 |
|---|---|---|
| ① 开场 | 30s | 一句话定位 + 技术栈 |
| ② 核心链路 | 2.5min | PDF → 提取 → 入库 → 台账（B1 灵魂） |
| ③ RAG 底座 | 1.5min | 提取结果 RAG 参照范例 + few-shot 对比数据（D 最大权重） |
| ④ 多智能体 + 业财 | 1.5min | 审查回路 + 收付款计划（D5/B5） |
| ⑤ Odoo 集成 | 1.5min | 模型驱动 + 三个解耦（C 高级解） |
| ⑥ 架构 + 数据 + 收尾 | 1.5min | 全链路白板 + 准确率数字（F/G） |

---

## ① 开场（30s）

**屏幕**：浏览器打开系统首页 `http://127.0.0.1:8000`

**口播**：
> 这是一个「提示词工程 + RAG 底座 + 业务系统 + 编排评估」四层协同的 AI 合同系统。企业要的不是会调 API 的人，而是能把 AI 落地到业务里的人——这个系统就是用 AI 工程方法解决合同变量提取、分类、业财一体化三个真实业务问题。

---

## ② 核心链路演示（2.5min）—— B1 合同变量提取

**屏幕操作**：
1. 上传 `data/filled_contract.pdf`（已填好的 48 万采购合同）
2. 页面显示「文字版」分流结果（点出 PDF 场景分流，为后面 OCR 埋钩子）
3. 展示 13 个字段回填：名称/编号/甲乙双方/金额+大写/日期/付款方式/违约/争议解决
4. 点「入库」，切到「已入库合同台账」看到该合同
5. 快速点「状态流转」：草拟→审批（演示状态机拦截非法流转）

**口播要点**：
> 上传 PDF 后，系统自动判断这是文字版 PDF，直接文本抽取、不走 OCR。LLM 用 JSON Schema 约束输出，字段枚举约束 + 解析失败自动重试。金额 480000 同时校验出大写「肆拾捌万元整」。

---

## ③ RAG 底座演示（1.5min）—— D1/D2 最大权重

**屏幕操作**：
1. 回到刚才上传合同后的「提取结果」，展示「RAG 参照范例」列——显示本次提取实际命中的范例（类型 · 范例ID · 相似度）
2. 切到终端，贴出 `scripts/evaluate.py` 输出

**口播要点（关键数据，务必说）**：
> 向量库里预置了 10 条正确范例（5 类各 2 条）。新合同先进向量库做相似检索，把最像的范例当 few-shot 注入提示词——这叫「把 RAG 当监督学习用」，不训练模型。10 份金标准盲测：无 few-shot 98.5%，有 few-shot 100%，提升 1.5%，且 few-shot 修正了 2 处错误。切块是按「一行一条款」语义切，不是无脑 500 字硬切。

---

## ④ 多智能体 + 业财（1.5min）—— D5 / B5

**屏幕操作**：
1. 台账点「审查」按钮，展示审查结论 + 回路轨迹（pass/supplement/人工介入）
2. 台账点「业财」按钮，展示自动生成的收付款计划（期次/方向/比例/金额/触发条件）

**口播要点**：
> 审查用 LangGraph 编排，有状态、有回路——审查发现风险会回头补材料重新审。线性提取用 LangChain LCEL，无状态一遍跑完，两个场景各用对框架。业财一体化：从合同付款方式提取分期节点，自动生成收付款计划——合同是业财一体化的依据。

---

## ⑤ Odoo 集成（1.5min）—— C 框架选型 5 分档

**屏幕操作**：
1. 切到 Odoo `http://localhost:8069`，展示「合同管理」应用
2. 新建合同 → 上传 PDF → 点「从 PDF 导入」→ 字段自动回填
3. 点「生成付款计划」「检索相似范例」

**口播要点（说清三个解耦）**：
> 这是 Odoo 自定义模块，只写 addons、不改 Odoo 源码，自建了合同/相对方/收付款计划三个 model。三个解耦：业务解耦——AI 计算全部走 HTTP 调外部 FastAPI，Odoo 只存业务结果；技术解耦——LLM 和 Embedding 在 .env 里可替换；编排解耦——LangChain/LangGraph 编排层独立在 app 里，Odoo 无感知。

---

## ⑥ 架构 + 准确率数据 + 收尾（1.5min）—— F / G

**屏幕**：切到 README 的架构图和「已知评估数据」表

**口播要点（全链路白板 + 数据汇总）**：
> 全链路：PDF → 场景分流 → 按条款切块 → Embedding 向量化 → 余弦相似检索 top-k 范例 → few-shot 注入 Prompt → LLM 结构化输出 → Schema 校验 → 失败重试 → 入库 → 业财/审查。
>
> 关键数据：提取准确率 few-shot 100%；分类 100%；OCR 文字版与扫描版各 100%；RAGAS 四指标已出报告并做了一轮改进闭环。代码在 GitHub，有 Docker、一键启动、一键测试，提交记录连续可见。

**收尾**：
> 一句话总结：这套系统把「提示词、RAG、编排、评估」四件套跑通了，正是考核强调的「能把 AI 落地到业务里」。
